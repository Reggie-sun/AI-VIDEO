# Ad Creative

为商品广告决定受众为何停留、产品解决什么、用什么表达机制讲清，以及结尾如何兑现开头。
这是本地广告创意专项；Product Truth、claim/source 和商业 authoring contract 继续归
[Ecommerce Ad Workflow](../ecommerce-ad-workflow/SKILL.md)，镜头统筹归
[open-video](../open-video/SKILL.md)。不建立第二广告 package、项目状态或执行流程。

## Default Product Video Direction

本项目新创作或获准整体重构的商品广告视频，必须落实以下内容方向；用户当次明确另定风格或
要求忠实复刻时遵从。只改颜色、字幕、单句或指定片段，不据此擅自重做已批准的整片。

- **生成与交付固定720p。** 按[广告制作要求](../ecommerce-ad-workflow/SKILL.md#fixed-720p-output)落实，不自行升至1080p或4K。
- **前3秒是夸张钩子。** 第一秒就让观众看见异常/反差，在0–3秒用夸张动作、戏剧性反差或直观视觉隐喻
  形成能看懂的事件，并把使用问题与商品本体或使用动作联系起来；不只靠大字、强音效或口播
  宣布“震撼”。3秒内必须出现可辨识的真实商品本体或包装，不能用抽象特效或末尾落版代替。
  夸张仍受 Product Truth 约束，不能编造实际功效。
  用户要求“浮夸”时，第一秒就要发生强烈尺度反差、突发大动作或连锁反应，前三秒形成清楚的
  事件升级；微缩装饰、静态奇景、普通惊讶表情或缓慢揭示不能单独算达标。冲击来自实际画面，
  不能只在 Prompt 中写“极度夸张”，也不能以强音效代替事件。
- **后续主体要有产品表现力。** 钩子之后尽快进入连贯的商品展示：看得清本体、材质/结构与
  尺度，读得懂关键使用或展示动作及其反馈，并由具体画面承载可支持的卖点。按品类选择有效
  信息，可在同镜完成；不机械规定镜头数或商品露出比例。
- **剧情和笑点回到产品。** 主要夸张事件要回扣真实商品、使用问题或人物使用反馈；产品要参与
  行动与转折，不能大段演无关剧情，只在最后亮包装。换景与否由表达决定，因果、动作和声音
  要连续；结尾用真实商品与品牌收束并兑现开头。
- **先让观众看懂处境与因果。** 尽早用画面交代人物在哪里、遇到什么、为何需要产品；按问题→
  人物动机→使用动作→可支持的效果/反馈→结尾回扣组织事件。不能开盖后凭空响警报，再硬接
  产品介绍；也不能只有开局夸张，中段缺少产品功效的具体表现。夸张应延续到与卖点有关的动作、
  反馈或视觉隐喻中，不能用无关奇观撑时长。
- **品名、声音与剪辑也是创意交付。** 将用户要求的完整产品名写进明确说话人的对白或旁白，
  留足正常语速与反应时间，不能只在包装或字幕中出现。每个接缝都要规划并复核剪辑，尤其是
  首尾帧接镜；首尾画面相似不等于声画已经连续，不能把多个生成片直接拼接当作完成。
- **空间特效必须随其所属对象运动。** 脸颊上的角色、营地或其他场景内元素须跟随头部/物体的
  位移、转动、透视与遮挡变化，保持接触关系并允许角色独立表演；不能像固定在屏幕上的贴图。
  要检查实际运动过程，静帧里位置看似正确不能证明运动附着通过。
- **按观众看到的内容复核。** 前3秒能否看出异常、问题及商品关系？后段能否看清是什么、怎样
  使用/展示、哪一处画面支撑卖点？删掉产品或换成无关商品后，剧情是否仍完全一样？缺少这些信息
  就修改创意或选材，不用持续解说、密集转场、末尾产品卡或技术通过代替商品表达。

这是广告内容的默认作者要求，回填既有 G2/G3/G5 并按实际成片复核；不新增 Runtime Gate，
不保证留存、转化或模型必然执行。具体 Hook 与视频组织分别见下列参考。

## Respect The Approved Brief

用户要求先讨论剧情时，先交代完整因果、产品功效如何入戏及结尾兑现，确认后再交制作 owner。
用户要求先做好一条时，集中打磨该条，不继续扩成多条试片。已认可部分的动作、画面、节奏和
声音须在修复后保留；用户明确否定的版本记为拒绝，不能沿用较早的人审认可替新版本签收。

时长、完整品名、水印文字与披露等具体商品 brief 归该项目的 spec/plan，不写入本 Skill。
brief 要求商户水印时，水印跨 Shot 连续，不在每个 Shot 重启或重复叠加；AI披露避免重复叠印。

## Select Only The Needed Work

- 新广告、角度、Hook、文案或根据已有数据迭代：读 [Strategy And Hooks](references/strategy-and-hooks.md)。
- 视频创意、商品演示、剧情广告、视觉隐喻及声音表达：读 [Video Creative](references/video-creative.md)。
- 只修指定字幕、Hook 或表演时，保留其余已批准事实、台词、时长、连续性与声音，不重新开发整片。
- 独立短剧/剧集归 `drama-authoring`；人物情节、悬念或对白服务商品广告时仍保留广告归属，可借用共用导演方法。

## Ground Facts Before Claims

先读取已提供的商品资料、产品图、品牌要求、目标观众、时长/画幅和已接受创意。区分可核实事实、
用户要求、创意补充及未知项。数字、效果、使用方式、评价、见证和比较结论必须有具体来源。
评价中的感受不自动变成普遍功效；不虚构销量、原价、限时、专家背书或“已验证爆款”。

冷启动可以从现有商品事实和明确标注的创意假设提出方案；没有历史投放或评价不妨碍做第一支片，
但不能声称该角度已经转化有效。需要缺失的功效事实时，删去无据主张或澄清关键缺口，不能把
想象的使用结果当证据。批量复刻赢家或数据迭代必须实际有对应输入，不能虚构赢家和学习结论。

## Return To Existing Owners

按请求交付一个完整创意或必要对比，说明受众处境、角度、可支持的承诺、表现机制、开头与
兑现方式、商品职责、声音和关键不确定项；只要 Hook 时不强制返回整套表单。

将策略建议回填现有 G1、Hook/因果 beats 回 G2、商品呈现回 G3、文案与声音回 G4、镜头意图回
G5，再由现有 owner 完成 G6/G7。素材/事实不完整时可交有边界的建议，不能声称 package ready。
不得通过创意建议解除现有 truth/rights、capability 或媒体 blocker。

`runtime_skill_calls = 0`。不运行上游工具、读凭据、接广告账户、创建/调整 campaign 或预算；
不选择 Provider/renderer，不生成、提交、轮询、重试或发布媒体，不改 Registry/Manifest、
timeline、P6 或 Final Acceptance。CTR/CVR/ROAS、留存及传播效果只由真实结果观察。

固定来源、许可及本地改写边界见 [Upstream Sources](references/upstream-sources.md)。
