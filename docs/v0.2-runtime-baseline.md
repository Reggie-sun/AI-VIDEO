## Current Product Contract

- 当前产品是 local-first Python CLI；ComfyUI 默认必须是 loopback host，非本地 ComfyUI 需要 `allow_non_local: true`。
- 公共命令只有 `ai-video validate`、`ai-video run` 和 `ai-video resume`。
- `validate` 不创建 run、不上传素材、不提交生成任务。
- Manifest v1 和 flat `runs/<run_id>/` layout 仍是 runtime truth。
- Legacy generation path 仍只有 Wan/ComfyUI；v2 P3/P4 另有显式 Python API 驱动的本地 HyperFrames composition/render path。P4 提供 provider-neutral voice contract 与 ElevenLabs thin opt-in adapter，但没有默认或已授权的 live Provider path，也没有 Remotion、Captions.ai 或其它 renderer。
- Legacy final composition 仍是 silent-video normalize + stitch；`ffmpeg_tools.normalize_clip()` 和 fallback stitch 都显式使用 `-an`。这不改变显式 v2 P4 HyperFrames audio/caption render path。
- P2 只通过 `ai_video.production.load_production_project()` 暴露；不增加 CLI 或改变 Legacy loader。
- P2A/P3/P4/P5/P6 只通过 Python API 暴露：`ProductionStateCommitter`、project/registry/voice/graph/review/repair commit、audio/caption contracts、render lifecycle requests、`render_with_hyperframes()`、pure dependency/review decisions 和 explicit recovery；不增加 CLI 或改变 Legacy Manifest v1/layout。

## Verified Implemented Behavior

- YAML + Pydantic config loading，以及相对路径到干净绝对路径的解析。
- API-format 和 UI-graph workflow 都通过 production loader 加载。
- Template + binding 渲染 prompt、seed、init image、resolution、frame count、generation FPS、output prefix 和 character reference，而不是在 pipeline 中写死 node ID。
- 顺序 Shot execution、bounded typed-error retry 和 optional last-frame chaining。
- `CharacterProfile` 与 reference image config；当前 pipeline 只上传并哈希每个 Character 的第一张 reference image。
- terminal failed Attempt、Shot failed state 和 Run failed state 在异常逃逸前通过 `atomic_write_manifest()` 持久化。
- Resume 验证 Shot clip/last-frame hashes，并对真实消费 previous frame 的 direct consumer 比较 `chain_input_hash`；same-hash regeneration、explicit `init_image` 或不存在 binding 时停止传播。
- Attempt-qualified staging、canonical artifact promotion 和进程内 rollback，避免 failed resume 覆盖上一次成功 clip/frame。
- `shot.fps` 只覆盖 workflow generation；`defaults.fps` 同时作为 generation fallback 和固定 delivery normalization FPS。
- ffmpeg/ffprobe clip validation、last-frame extraction、normalize、stream-copy stitch 和 re-encode fallback。
- Project-local `video-analysis` MCP 提供 probe、frame extraction、Whisper transcription、scene detection、heuristic review、optimization planning 和受限的 config/shot edit 建议。
- Strict/frozen v2 `ProductionProject`、`ProductionBrief`、`Story`、`Character`、`Scene`、`Storyboard` 和 `Shot` schemas，未知字段被拒绝。
- Deterministic artifact envelope hash 与 exact `ArtifactReference`；Production Manifest 同时固定 active project revision/content hash 和 registry revision。
- 六种 Shot `visual_strategy` 的 static validation，包括 concrete role-to-asset ID/type/source binding、deterministic motion directive 和 explicit hybrid layers。
- Read-only content-addressed Asset Registry verification：duplicate ID、revision filename/content hash、local file size/SHA-256 和 typed provenance fields。
- `project.yaml`、`state/`、`creative/`、`assets/` 和 `asset_root` 的 traversal/symlink containment；internal symlink 只在 resolved target 仍留在对应 boundary 时允许。
- P2 loader 无网络、不创建目录、不改变 input mtime，且保留 `ASSET_REGISTRY_INVALID` 与 `PRODUCTION_PROJECT_INVALID` 错误分层。
- P2A 的 `ProductionManifest` 是 v2 project/registry state lifecycle 的单一 owner；其 nested active pointers 固定 exact relative path、semantic revision/content hash 和 file SHA-256。`project.yaml` 仍是稳定且会被验证的 entrypoint，但不是 active snapshot bytes truth。
- `ProductionStateCommitter` / `state_commit.py` 是唯一 v2 writer/recovery owner：POSIX 同一文件系统下用 `state/commit.lock`，immutable snapshot temporary write + file fsync + promote-without-overwrite + parent-directory fsync + reopen verification。Manifest 还会 durable record running/failed attempt lifecycle；仅 final active-pointer atomic replace 是 single logical commit point。
- P2A recovery 只能显式调用，不会在 reader load 中自动执行。它只接受完整 old pair 或完整 new pair；mixed/tampered active state 失败而非猜测。它只清理 bounded、non-succeeded attempt 的 owned temp files，并 preserve/report complete orphan snapshots，不删除、不激活。
- P3 的 strict `CompositionSpec` 解析为 sealed `ResolvedTimeline`；后者是唯一 frame/sample order 与 timing truth。当前只接受 local PNG/JPEG/WebP `STATIC_IMAGE`、deterministic transform/z-order/opacity 和 zero-duration `CUT`。其它 visual strategy、motion directive、crossfade 和 Remotion selection 明确失败。
- P3 固定 `hyperframes@0.7.103` 与已验证 Chrome Headless Shell `152.0.7928.2`。每个 version/doctor/lint/check/render tool process 都进入 fresh user/network/PID namespace；非 version 命令必须带 root `--json`，controlled env 不继承 proxy/credential，且没有 host 或 alternate-renderer fallback。
- HyperFrames source 使用 root boolean `data-no-timeline`、root-only duration、clip frame/sample metadata 与 capture-safe CSS opacity keyframes。结构化 URL/raster/source audit、lint/check JSON、bundle hash 和 phase rehash 在 render-state activation 前完成。
- `render_with_hyperframes()` 在任何 executable 前 durable begin；普通 pre-activation failure 由 outer lifecycle 终结，进入 `activate_render_state()` 后的 candidate/final 四个窗口由 P2A writer 独占。成功路径是 R+1 selection、R+2 candidate-prepared、R+3 single `active_render_state` switch；不确定 replace outcome 必须 explicit recovery。
- Canonical immutable layout 位于 `state/render/{timelines,sources,source-receipts,render-receipts,outputs,states}/`；scratch 位于 safe attempt root 且不进入 semantic receipt。输出 hash、size、ffprobe metadata、framemd5 fingerprint 和 durable bytes 全部绑定同一 held verification FD。Verify failures统一为 P3 `RENDER_FAILED`，不泄漏 `FFMPEG_FAILED`。
- Production Manifest 2.0/2.1/2.2 继续只读兼容；2.0 的首次 render lifecycle write 原子迁移到 2.1，已有 2.2 不会被降级。2.0-2.2 保留历史 project/registry pair-change pointer behavior；Manifest 2.3 不再用 blanket stale，而由 P5 dependency states 精确比较 desired/applied。Immutable source/output/state evidence始终保留；recovery 使用 exact selected identities 并 preserve/report complete render orphans。
- P4 将 `dialogue | narration | ambience | sfx | bgm` 建模为 first-class audio kinds。Local import 与 generated speech 都记录 source、speaker/voice、language、script hash、duration、sample rate、channels、loudness、timing、gain/fade/ducking 和 typed provenance；物化后必须 probe、hash、reopen verify 再进入 registry。
- Provider-neutral `VoiceAssetProvider` 接收 immutable/self-sealing `VoiceGenerationRequest`。提交前必须完成 deterministic budget/egress preview 与 authorization；P2A 先写 R+1 request，再写 R+2 submit intent 并签发 committer-issued one-use permit，随后才允许 provider call。Provider outcome 绑定 materialized audio、alignment、cost、policy/retention 与 provenance receipts；R+3 candidate graph 验证完成后才由 R+4 atomic Manifest activation 切换 exact Registry 2.1 revision。
- Canonical `CaptionTrack` 记录 script/transcript identity、segments、optional words、half-open start/end、speaker、segmentation policy、confidence/provider、style reference 与 timing fingerprint。它是 structured source 而不是 burned-in pixels；selected HyperFrames renderer 负责 layout/drawing。
- P4 通过 `CompositionSpec.audio_tracks` / `caption_tracks` 扩展既有 P3 contract，并由同一个 `ResolvedTimeline` 解析 canonical `audio_spans` / `caption_cues`。该 timeline 继续独占 order、frame、sample 和 timing；不存在第二条 canonical audio timeline。
- HyperFrames 只消费已解析的 timeline，按 canonical order deterministic mix gain/fade/ducking，并在同一次 selected-renderer invocation 中 mux audio、按 half-open cue window 绘制 captions。Source/output/receipt 验证继续在 P2A activation 前完成；caption pixels 不是 `CaptionTrack` 的持久化真相。
- `ProductionStateCommitter` 仍是唯一 v2 writer/recovery owner。Voice lifecycle 的 R+1/R+2/R+3/R+4、audio import 和 render activation 都写同一个 `ProductionManifest`；成功 P4 lifecycle 使用 Manifest 2.2，Registry/Composition/ResolvedTimeline 继续使用 2.1 extensions。2.0/2.1 reader 与 2.1 recovery 的 forward compatibility 保留，禁止 schema downgrade、第二 Manifest、第二 registry writer 或 automatic recovery。
- Provider call 后任何不能确认 authoritative outcome 的 crash window 都持久化为 `outcome_unknown`，explicit recovery 不会 remint permit 或 blind resubmit。Exact replay 不重复调用 provider/renderer；tampered/stale/mismatched evidence fail closed，pre-activation failure 保持旧 active triple，complete orphan 只 preserve/report。
- 默认 acceptance 使用 committed deterministic WAV/caption/style fixtures、fake provider/fake transport 和 no-network tests。ElevenLabs 只是显式 opt-in concrete candidate，adapter 不从 `ai_video.production` package root 导出；本 slice 未安装 SDK、未读取 secret、未使用免费或付费 quota、未发起 live call。真实调用即使账户有免费额度也必须另获授权，并重新通过 budget、egress、secret redaction 与 crash-safe request/outcome persistence gates。
- P5 `DependencyGraphSnapshot` 2.0 是 immutable、content-addressed/versioned resolver input，只保存 typed nodes、typed edges、`DependencyReason` 与 fingerprint contributions。它没有 desired/applied、fresh/stale/failed/blocked/superseded 或其它 mutable status，也不计算 Shot order、frame、sample 或 timing。
- `ProductionManifest` 2.3 是 `active_dependency_graph`、per-node desired/applied fingerprints 与 lifecycle 的唯一 owner。Desired fingerprint 由 canonical local contributions、typed edge contribution 与 upstream desired 递归组成；无变化输入停止传播，变更只让精确 transitive dependents stale/blocked。Failed same-desired 保留且不auto-retry；changed desired重新进入stale ready frontier；exact replay无execution unit与state advance。
- P5 显式消费 P2 creative/registry semantics、P3 CompositionSpec/opaque ResolvedTimeline/render contracts，以及 P4 voice、audio、alignment timing、caption style与mix inputs。`ResolvedTimeline` 继续独占 order/frame/sample/timing；Graph 不重算或另造 canonical timeline。
- CompositionSpec、ResolvedTimeline、renderer source与render是一个durable `render_with_hyperframes` execution unit；四个node只有在final `RenderStateSnapshot` activation后才能在同一个Manifest replace中一起fresh。旧render pointer不能证明新composition/timeline，`record_dependency_node_applied()`不得分别推进这四个node。
- `ProductionStateCommitter` 继续是唯一 Manifest、registry、render与graph writer/recovery owner。Canonical graph snapshot 位于 `state/dependency_graph.<revision>.json`；project/registry/voice/render/graph activation共用同一个 final Manifest replace commit point。Graph temp write/fsync/promotion/directory-fsync/verification/final replace crash windows、unknown outcome、partial/temp/orphan snapshot、forward-compatible reader/recovery与idempotent replay均fail closed；不存在第二 graph writer或automatic recovery。
- Required mutation matrix 使用 two-Shot、two-visual、two-voice、two-caption/style、BGM/SFX、real deterministic ResolvedTimeline 与 fake source/render receipts，证明 script、voice settings、alignment policy、caption timing/style、audio mix、visual asset、CompositionSpec、renderer source/render contract只重建精确节点；alignment receipt在timing fingerprint不变时不会制造blanket stale。Generated-image future seam只接受strict synthetic `AssetRecord`，没有实现P7 provider。
- P6 将 QA policy、ReviewRequest、ReviewEvidence、Review Receipt、RepairRequest、Approved Repair Receipt、Repair Outcome 与 Final Acceptance 建模为 immutable、versioned、content-addressed evidence；Manifest 2.4 独占 selected policy、review lifecycle、active approval/outcomes/final acceptance，P5 graph仍不保存 mutable review status。
- `ProductionStateCommitter` 在 lock 内从 verified `LoadedProductionProject + ResolvedTimeline + Shot.visual_strategy` 生成并重验 non-empty、无遗漏/重叠的 technical windows，durable consume review intent后才签发 process-local one-use analysis permit。`video-analysis` 只消费 permit并收集 raw luminance/audio/frame evidence，不写 Manifest、不判 Production verdict；公开 MCP surface不能绕过 committer。
- Technical、layout、strategy、semantic 与 final acceptance 分层 fail closed。合法 `static_image` 不因低 frame diversity失败；video-like strategy 的 genuine frozen、black、silent、clipped evidence由 selected policy裁决；semantic PASS必须来自 policy-selected evaluator/human identity，heuristic、console text或Agent memory不能自我升级。
- Repair approval默认关闭，必须由 injected trusted authorizer返回 policy-selected actor；authorization、exact targets与P5 transitive invalidation closure被 sealed receipt绑定。只有 approved repair能进入现有P5 transition；exact replay不重复analysis/repair/render，unknown outcome不blind retry，rerender后必须有current fresh review才能记录outcome或final acceptance。
- QA policy-only变化只 stale affected review state，不重建asset/render。render state、output hash、timeline、graph或policy identity变化会使旧review/final acceptance失效；Composition、ResolvedTimeline、renderer source与render继续只由同一次final render activation原子fresh。

## Remaining Runtime Defects and Debt

- Succeeded resume fast path 只检查 Shot clip/frame 与 direct chain dependency，不检查 normalized clips 或 `final.mp4`。删除或损坏 final output 后，resume 仍可能直接 no-op。
- `project_config_hash`、`workflow_template_hash` 和 `workflow_binding_hash` 已记录但 resume 不比较。Prompt、explicit init image、character reference、config 或 workflow 变化仍可能被成功 fast path 跳过。
- Attempt 的 `running` state 和 Comfy prompt/job ID 没有在 submit 前后 crash-safe 持久化。进程或主机中断可能丢失 in-flight provenance，并留下 blind resubmit 风险。
- Legacy final output 没有 content hash；Legacy run multi-file artifact transaction 没有 journal/fsync 级 power-loss recovery。
- `CharacterProfile.reference_images` 接受多张图片，但当前 pipeline 只消费第一张；`future_lora` 仍只是 config placeholder。
- Whisper MCP 的 `word_timestamps=True` 会传给模型，但返回 schema 丢弃 per-word records，cache key 也没有包含该 flag；它不能直接作为新 Caption domain 的 word-timing owner。
- Legacy heuristic review仍可能把低帧差或少 scene标为 `static_visuals`；P6 Production path已与其隔离，并以verified Shot strategy和timeline windows判定，Legacy提示不得作为Production acceptance evidence。
- Legacy FPS 行为已经被测试锁定，但一个 `defaults.fps` 字段仍同时表达 generation fallback 和 delivery FPS；新 domain 需要分开建模，不能回写改变 Legacy semantics。

## Retained Legacy Design

- Manifest-first provenance、hash、resume 和 atomic persistence 思想继续保留。
- Local Wan + ComfyUI 继续作为 optional `generated_video` asset capability；不删除、不降级现有 CLI。
- Workflow loader、renderer 和 Comfy client 的现有 owner boundary 继续保留；未来 adapter 只能组合它们，不能复制。
- `_ArtifactPromotion` 的 staging/rollback 设计继续用于 Legacy runtime；P2A 已由独立 `ProductionStateCommitter` owner 提供 v2 project-state commit/recovery boundary，未改变 Legacy artifact transaction。

## Superseded Product Assumptions

- `Shot = prompt to video model` 不再是 v0.2 顶层 domain。
- Provider abstraction、Take 和 Seedance 不再是新 v0.2 的第一条主线。
- “所有 Shot 都生成视频”不属于目标；基础 AI 漫剧必须在没有 Video Provider 时完成。
- 旧 spec 的 P0-P9 ordering 已被新 roadmap 取代；其 paid-provider safety contracts 仍可复用。
