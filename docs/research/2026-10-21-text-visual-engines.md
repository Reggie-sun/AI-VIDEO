# Text and Motion-Graphic Engines for AI-VIDEO

Research snapshot: 2026-10-21

## Decision

在 AI-VIDEO 中保留 `CompositionSpec → ResolvedTimeline → HyperFrames` 为唯一 Production 组合与时间轴路径。对白、双语字幕和逐词强调可以采用 `pysubs2==1.8.0` 生成或校验 ASS 数据，再由版本固定的 libass native API 按 `ResolvedTimeline` 指定的帧栅格化为透明 PNG data URI，作为 HyperFrames immutable source 的编译产物；广告、片名和章节图文继续由 HyperFrames 浏览器 scene graph 渲染。`fontTools` 可作为 optional extra 检查被选字体的名称表和字形覆盖。

这条选择的依据是：libass 专注 ASS/SSA 字幕渲染，pysubs2 负责跨格式字幕数据，不承担渲染；广告与标题需要更广的布局和运动表达，适合在当前 HyperFrames source compiler 中继续扩展。`Revideo` 与 Motion Canvas 都能做丰富的代码动画，但引入它们会增加完整 Node/browser 渲染体系及第二套 scene/timing 语义；Remotion Captions 包主要处理字幕数据，不是可独立接入的通用渲染器。上述选型不会自动产生专业设计：Director 仍须依据叙事、构图、角色、品牌和节奏创作层级、位置、运动与时机，QA/Review 仍以 exact 成片和既有证据链裁决。

## Inspected AI-VIDEO Baseline

当前 [commercial graphics contract](../../src/ai_video/production/commercial_graphics.py) 有有限的 graphic-role 和 entrance/exit 枚举，主要以位置、宽度、字号、字重、字距、颜色和底色描述单层文字；[HyperFrames source compiler](../../src/ai_video/production/_hyperframes_source.py) 将这些字段变成 HTML/CSS，关键词强调目前是粗体下划线，动态图文采用固定时长的淡入、位移或缩放 keyframes。字幕已走独立 CaptionTrack/ResolvedTimeline cue 路径，保留字幕资产和样式 identity。Production 仍要求 HyperFrames 默认渲染器、唯一 `ResolvedTimeline` 以及现有 QA/Review/Repair 生命周期，见 [runtime baseline](../v0.2-runtime-baseline.md) 和 [surface matrix](../agent-primary-contract-matrix.md)。

因此升级要区分三件事：libass/浏览器解决渲染能力；Creative intent/Director 决策解决设计选择；模型能力不足时仍需要有界的人类设计输入或针对真实素材的迭代证据。更强的渲染引擎本身不能决定视觉主次，也不能证明字体适配、避让主体或镜头运动下的可读性。

## Recommended Integration Boundary

1. Keep Director-authored text layers and their visual purpose in the existing creative/composition handoff. The data must be expressive enough for different layer counts, text runs, alignment/anchors, safe-area constraints, per-layer style and timing, and independent motion/transition curves; a new closed set of `GraphicRole` values would preserve the current design ceiling.
2. Keep all authoritative frame/sample placement in `ResolvedTimeline`. Convert its cue/layer intervals into ASS or per-frame libass calls; do not accept ASS event times as an independent timeline. Bind the font bytes, libass library version, authored input identity and raster bytes into deterministic compiler provenance. The existing source audit should reproduce or validate the exact allowed PNG data URIs before source use.
3. Use libass only for the subtitle treatments that benefit from ASS text shaping, outline, karaoke or animation semantics. Keep advertising and title motion in the HyperFrames scene graph so it can use multiple authored layers and browser layout without adding a full second renderer.
4. Pin `pysubs2==1.8.0` as an optional ASS/data extra compatible with Python 3.11. Keep `fontTools==4.67.0` optional if font coverage/name validation is needed. Do not install PyonFX in the default runtime; revisit it only after a real stylized-caption pilot demonstrates a feature gap that libass plus current authored intent cannot express.

Raster data URIs make immutable HyperFrames source self-contained and can avoid temporary-file authority, but increase generated HTML/source size and browser memory. A warm cache may reduce repeated work only for identical font bytes, subtitle style, text, frame size, libass build and resolved frame; no speed claim should be made before measuring the actual pilot. Native-library call throughput, source size, browser capture time and final MP4 quality are distinct measurements.

## Evidence Limits and Pilot Checks

No official head-to-head benchmark among these projects measures Chinese dialogue subtitles, bilingual safe-area placement, karaoke highlighting or branded title animation at AI-VIDEO's output sizes. Native C, parallel rendering, recent commits and stars are not quality or throughput proofs. For the pilot, use the same footage, frame size, timing and exact text to compare current HTML/CSS against the selected subtitle path, then separately test an advertising/title composition in HyperFrames. Inspect exact normal-speed output for Chinese glyph coverage, line breaks, clipping, face/product occlusion, camera movement, frame-boundary timing and motion rhythm. A technical renderer pass must remain separate from Director/design review and existing QA/Review acceptance.
