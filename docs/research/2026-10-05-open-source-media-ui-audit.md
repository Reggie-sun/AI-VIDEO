# Open-Source Media and UI Reuse Audit

## Scope and snapshot

本报告只覆盖 Wind Comic 的媒体合成/导出、TTS/字幕/lipsync、媒体工具、片段重拍 UX、项目持久化，以及 GPL AI Video Production Editor 的 UI/导出。Provider client 与后端 recovery/security 由主审计负责。AI-VIDEO 依据已提交的 `main` 快照 `4cc1b55d81c881711175c71fa18a1f4d7326c92f`（抽取到 `/tmp/ai-video-reuse-audit-20261005/AI-VIDEO-main`）；Wind Comic 与编辑器快照分别为 `82bedb596336fc09ee85240ccf211b0edc53ef4d` 和 `752cd43d3af6421d2bd6d4ce27f2d9815f7acba3`。

截至 2026-10-05 的仓库 metadata 记录：Wind Comic 为 620 stars / 72 forks，最近 push 是 2026-10-04；编辑器为 62 stars / 10 forks，最近 push 是 2026-10-01。这些数据只表示活跃度与采用度，不代表实现质量。Wind Comic 的根目录 `LICENSE` 和 `package.json` 均声明 MIT；编辑器根目录 `LICENSE` 为 GPL-3.0。复制 Wind 代码须保留版权与许可文本；除非 AI-VIDEO 明确接受 GPL 义务，编辑器代码只作参考。

## Security, implementation maturity, and reuse boundary

Wind Comic 配有 `npm test`、`npm run test:e2e`、`npm run typecheck`，并有导出滤镜计划、字幕路径转义和帧对齐重拍测试。本次只检查测试源码，未执行这些测试。纯 planner 是最适合评估复用的实现；测试覆盖和功能广度不能替代服务层安全审查。

`services/video-composer.ts` 的 `downloadFile` 会递归跟随 redirect，代码中未见跳数上限或逐跳目的地址重验；它接受任意 `http`/`https`，并从 `/api/serve-file?path=` 解码本地路径后直接复制存在的文件。 [download path](https://github.com/ChrisChen667788/wind-comic/blob/82bedb596336fc09ee85240ccf211b0edc53ef4d/services/video-composer.ts#L396-L455) 复用前需解决 SSRF 与本地路径穿越风险。同一文件部分操作使用 shell-form `exec`，且以 `execSync` 查找 binary。 [shell helper and resolver](https://github.com/ChrisChen667788/wind-comic/blob/82bedb596336fc09ee85240ccf211b0edc53ef4d/services/video-composer.ts#L34-L82) 不要复制该 shell wrapper。AI-VIDEO 的 HyperFrames 路径有专用 executable/argv/timeout 与 redaction 检查，但通用 `ai_video.ffmpeg_tools.run_command` 未设置 timeout，不能概括为所有 FFmpeg 路径都有界。 [generic runner](https://github.com/Reggie-sun/AI-VIDEO/blob/4cc1b55d81c881711175c71fa18a1f4d7326c92f/src/ai_video/ffmpeg_tools.py#L17-L28) · [HyperFrames timeout sites](https://github.com/Reggie-sun/AI-VIDEO/blob/4cc1b55d81c881711175c71fa18a1f4d7326c92f/src/ai_video/production/hyperframes.py#L1938-L1977)

Wind TTS service 直接读取应用 API config，并发送 MiniMax 专用 voice ID/settings，因此不是 provider-neutral。 [TTS binding](https://github.com/ChrisChen667788/wind-comic/blob/82bedb596336fc09ee85240ccf211b0edc53ef4d/services/tts.service.ts#L153-L230) 代码受 MIT 许可，可在保留 notice 后移植；credentials、provider selection、response parsing、retry、upload/download 与 persistence 仍须经过 AI-VIDEO 自有 effect boundary。

不要从零编写媒体 helper 前，先评估兼容 Python 与现有 FFmpeg seam 的成熟维护库。本次审查的仓库没有提供值得 vendoring 的轻量、独立且经过安全审查的 media utility package。Wind 依赖 `fluent-ffmpeg`、`ffmpeg-static`、`ffprobe-static`、`sharp` 与 Yjs；AI-VIDEO 已使用 FFmpeg/subprocess、Pillow 与 NumPy。继续通过 AI-VIDEO 现有边界调用 FFmpeg/ffprobe，不要仅为获取滤镜字符串引入 Wind 的依赖树。

## Recommendation

建议进入“核心自研、外围复用/适配”阶段。保留 `ResolvedTimeline`、HyperFrames、字幕/voice truth、accepted media evidence、Provider selection、attempts、state commit 与 QA/evidence lineage。后续首个有界迁移可做成**验收后画幅 derivative exporter**，适配 Wind `lib/video-export.ts#buildAspectFilter`。预期只新增 `src/ai_video/production/derivative_export.py` 与对应测试，并从验收后的 delivery/export surface 调用。此项不改 `composition.py`、`ResolvedTimeline`、`hyperframes.py` 渲染语义或 H3 continuity 路径。

当前没有值得先于 H3 continuity A/B 的 utility 迁移。先完成已授权的 H3 continuity evidence；之后若有产品需求，再把 derivative exporter 作为独立的成片后处理功能实现，使其不改变 canonical output 与 timeline。文档中的外部测试只做源码审查，未实际运行。
