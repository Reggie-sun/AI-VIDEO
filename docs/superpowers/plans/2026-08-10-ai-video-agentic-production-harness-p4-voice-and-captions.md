# AI-VIDEO Agentic Production Harness P4 Voice and Captions Implementation Plan

> **For agentic workers:** 实施本 plan 时，REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans。按 Task 顺序执行，并使用 checkbox (`- [ ]`) 跟踪进度。

**Goal:** 在 accepted P2/P2A/P3 contract 之上，把 voice、其他 audio 与 canonical captions 建成 provider-neutral、可持久化、可验证的 first-class production assets，并让唯一 `ResolvedTimeline` 与 selected HyperFrames renderer 以整数 sample/frame 边界确定性消费它们。

**Architecture:** `src/ai_video/production/models.py` 继续拥有 strict v2 schemas；新的 `audio.py` 拥有 audio probe/materialization、immutable voice request 与 provider-neutral contract，新的 `captions.py` 拥有 alignment normalization 与 canonical `CaptionTrack` 构造，新的 `elevenlabs.py` 只是显式 opt-in thin adapter。现有 `composition.py::resolve_composition()` 与 `ResolvedTimeline` 仍是唯一 order/frame/sample/timing owner，现有 `hyperframes.py` 仍是唯一 selected renderer adapter，现有 `state_commit.py::ProductionStateCommitter` 仍是唯一 v2 writer/activation/recovery owner。P4 不新建 audio timeline、Manifest、registry writer、renderer、CLI 或 automatic recovery。

**Tech Stack:** Python 3.11+、Pydantic v2 frozen strict models、`Decimal`、`hashlib`、stdlib WAV/JSON primitives、现有 held-FD/hash/path-containment/P2A commit utilities、existing pinned HyperFrames renderer、pytest deterministic WAV/alignment fixtures、fake provider 和 injected fake transport。默认 acceptance 不联网、不读取 secret、不安装 ElevenLabs SDK、不发起 paid call，也不执行 live submit。

## Problem Boundary

P4 要扩展的当前 production path 是：

```text
Shot.dialogue / Shot.narration / VoiceProfile authoring inputs
+ explicit local/imported/generated audio intent
+ immutable VoiceGenerationRequest when generation is requested
        |
        v
VoiceAssetProvider preview -> explicit budget/egress authorization -> provider result
        |
        v
materialize -> held-FD probe -> hash -> alignment normalization
        |
        v
AudioAssetMetadata + CaptionTrack + receipts
        |
        v
P2A-owned candidate Asset Registry snapshot
        |
        v
CompositionSpec audio/caption bindings
        |
        v
composition.py::resolve_composition()
        |
        v
ResolvedTimeline (only order/frame/sample/timing truth)
        |
        v
selected HyperFrames source: structured caption cues + deterministic audio mix
        |
        v
measured audio/video output + RenderStateSnapshot
        |
        v
ProductionStateCommitter-owned activation/recovery
```

P4 的 product boundary 是：

- Audio 是 first-class domain，类型恰好为 `dialogue | narration | ambience | sfx | bgm`。
- Voice generation 只覆盖 `dialogue` 与 `narration`；`ambience`、`sfx`、`bgm` 通过同一个 canonical audio asset/track contract 导入或引用，但不被错误路由到 voice provider。
- `Shot.dialogue`、`Shot.narration` 和 `Character.voice_profile` 继续是 authoring inputs；它们不是 generated bytes、measured duration、alignment 或 active timing truth。
- P4 可以支持 fixed duration，并在严格条件下支持 `voice_driven`；`content_driven` 继续 fail closed。
- Captions 是结构化 `CaptionTrack` artifact。renderer 可以根据其 cue/style 生成画面，但不得把 burned-in pixels 反向当作 caption truth。
- P4 只扩展已经 selected 的 HyperFrames adapter；不增加 Captions.ai final-render path、Remotion adapter、ffmpeg alternate final renderer 或 cloud fallback。
- P4 不实现 P5 dependency graph/selective rebuild。它只产出未来 P5 可消费的 typed fingerprints 与 dependency inputs；registry 变化仍沿用现有 coarse `active_render_state=None` invalidation。
- P4 不引入 Video Provider、P5+、QA/repair、自动修复、第二 renderer、新 CLI 或 Legacy runtime mutation。

## Audio Domain Contract

### Audio Kinds and Registry Mapping

新增 `AudioKind` enum，取值必须恰好为：

| `AudioKind` | Intended Source | Registry `AssetType` | Voice Provider Allowed |
| --- | --- | --- | --- |
| `DIALOGUE` / `dialogue` | character speech | `VOICE` | yes, explicit request only |
| `NARRATION` / `narration` | narrator speech | `VOICE` | yes, explicit request only |
| `AMBIENCE` / `ambience` | imported/generated environmental bed | `SFX` | no |
| `SFX` / `sfx` | point/short sound effect | `SFX` | no |
| `BGM` / `bgm` | music bed | `MUSIC` | no |

`AssetType.CAPTION` 保存 canonical CaptionTrack bytes；`AssetType.VOICE/MUSIC/SFX` 保存 audio bytes。不得新增 `AUDIO` catch-all type来绕过已有 semantics。

### Audio Metadata

在 `models.py` 新增以下 frozen strict models：

```python
class AudioChannelLayout(str, Enum):
    MONO = "mono"
    STEREO = "stereo"

class AudioLoudnessMetadata(StrictModel):
    integrated_lufs_milli: int | None
    true_peak_dbfs_milli: int | None
    measurement_standard: Literal["ebu_r128"] | None

class AudioAssetMetadata(StrictModel):
    audio_kind: AudioKind
    source: AudioSource
    speaker_id: str | None
    voice_id: str | None
    language: str | None
    script_hash: str | None
    duration_samples: int
    sample_rate_hz: int
    channels: Literal[1, 2]
    channel_layout: AudioChannelLayout
    codec_name: str
    loudness: AudioLoudnessMetadata
    provenance_receipt_id: str
    alignment_receipt_id: str | None
```

`AudioSource` 明确区分 `imported | generated | derived`，并引用 provider/tool identity、input artifact IDs、input fingerprint 与 original source reference。`AssetRecord.audio_metadata: AudioAssetMetadata | None` 由 cross-field validator约束：

- `VOICE/MUSIC/SFX` 必须有 audio metadata；P2-era registry `2.0` records 可在 backward-compatible reader path 中保持缺失，但不得进入 P4 composition。
- 非 audio asset 不得带 audio metadata。
- `dialogue/narration` 必须有 `language` 与 `script_hash`；有 speaker 时保存 stable project `speaker_id`，有 generated voice 时保存 provider-neutral `voice_id`。
- `duration_samples`、`sample_rate_hz`、channels、codec 与 loudness来自 held-FD probe/analysis，而不是 provider claims或 filename。
- `duration_seconds` 仅保留为 legacy/generic display metadata；P4 timing 使用 integer `duration_samples`。若两者同时存在，按明确 Decimal tolerance 校验，绝不从 float 反向生成 canonical samples。
- `integrated_lufs_milli` 与 `true_peak_dbfs_milli` 使用 fixed-point milli-units；无法测量时为 `None` 并由 mixing acceptance policy fail closed或明确允许，不伪造零值。

Current `EgressMetadata`的`remote: Literal[False]`必须以backward-compatible strict union扩展：local variant继续要求destination/authorization均为`None`；remote variant要求canonical HTTPS origin、egress authorization receipt ID、request/payload fingerprint、declared retention mode和provider policy snapshot ID。只有registry 2.1 generated voice record可使用remote variant；secret/header/raw script不得进入egress metadata。old registry 2.0 local records保持byte/hash兼容。

### Track Placement and Mix Policy

`CompositionSpec` 新增 `audio_tracks: tuple[AudioTrackSpec, ...] = ()`：

```python
class AudioTrackSpec(StrictModel):
    track_id: str
    audio_kind: AudioKind
    asset_id: str
    shot_id: str | None
    start_sample: int | None
    trim_start_sample: int
    trim_duration_samples: int | None
    gain_millidb: int
    fade_in_samples: int
    fade_out_samples: int
    ducking: DuckingSpec | None

class DuckingSpec(StrictModel):
    sidechain_track_ids: tuple[str, ...]
    attenuation_millidb: int
    attack_samples: int
    release_samples: int
```

Contract：

- `dialogue/narration` 默认绑定一个 `shot_id`；`ambience/bgm` 可是 composition-global；`sfx` 可选择 shot-relative或 explicit sample start。
- `start_sample=None` 表示由 shot start解析；显式 start 是 composition-relative integer samples。禁止 float seconds。
- P4 initial acceptance要求每个selected audio asset的measured `sample_rate_hz`等于`CompositionSpec.sample_rate`；mismatch以`AUDIO_TIMELINE_INVALID` fail closed。不得让browser/renderer隐式resample。若未来需要canonical resampling，必须先增加独立derived-asset/probe/hash contract与授权，而不是在renderer中隐藏转换。
- trim/fade/ducking 的单位都是 composition sample rate 下的 integer samples；gain 使用 milli-dB。renderer不得重新解释成浮点 authored timing。
- 超出 source asset 的 trim、fade 总长大于 span、重复 track ID、未知 asset/shot、类型不匹配、sidechain self-cycle或未知 sidechain一律 typed-fail。
- 音频短于 visual timeline 时 deterministic silence-pad；长于 visual timeline 时仅在 explicit trim 后允许，未显式 trim则 fail closed；不得默默延长 fixed composition。
- `voice_driven` 只允许一个 designated dialogue/narration driver per shot。driver 必须是已注册且 probe 完成的 audio asset；shot duration取其 trimmed sample length并应用已声明 min/max bounds。多个 driver、无 driver、超界或无法 frame-snap均 fail closed。
- `content_driven` 在 P4 继续拒绝。
- mix order按 resolved `track_id` canonical order及 kind priority明确定义，不依赖 input tuple偶然顺序、filesystem order或 renderer DOM order。

## Voice Provider Contract

### Immutable Request

`audio.py` 新增 `VoiceGenerationRequest(StrictModel)`，使用现有 frozen config，并至少固定：

- `request_id`、`attempt_id`、`provider_kind`、`model_id`
- `audio_kind: dialogue | narration`
- exact `script_text` 与 `script_hash`
- `speaker_id`、provider-neutral `voice_id`、`language`
- explicit output container/codec/sample rate/channel request
- deterministic voice settings allowlist及其 canonical JSON hash
- project/registry base pointers
- input artifact IDs/fingerprint
- pricing snapshot ID、budget reservation receipt ID、egress authorization receipt ID
- canonical `voice_request_fingerprint`

`script_hash` 由 normalized UTF-8 exact script bytes计算；request必须同时保存 exact text作为 provider input artifact或contained durable request artifact。不能只保存 hash后在 replay 时从 mutable Shot重新取文本。canonical fingerprint包括 provider/model/voice/settings/language/output format/script hash，但排除 secret、volatile provider request ID、timestamps 和 cost outcome。

### Provider-Neutral Interface

定义最小 protocol：

```python
class VoiceAssetProvider(Protocol):
    def preview(self, request: VoiceGenerationRequest) -> VoiceGenerationPreview: ...
    def generate(
        self,
        request: VoiceGenerationRequest,
        authorization: VoiceCallAuthorization,
        permit: DurableVoiceSubmitPermit,
    ) -> VoiceProviderResult: ...
```

`preview()` 纯计算、no-network，返回：

- exact request fingerprint与字符/计量单位；
- pricing snapshot/version和 upper-bound estimated cost；
- egress destination、method、payload categories、script byte/character count；
- credential reference kind但绝不包含 secret；
- `paid_call_required`、`remote` 与 explicit policy decision；
- provider capability result：requested timing/alignment/output format是否有 verified adapter support。

`generate()` 只有在 durable request、budget reservation、egress authorization和 submit intent都已由 `ProductionStateCommitter` 持久化后才能被调用。provider返回 `VoiceProviderResult`：audio bytes、content type、provider request/trace IDs的 sanitized值、raw character timing或alignment payload、reported usage/cost headers和terminal status。provider不得写 project paths、registry、Manifest或receipts。

为避免direct adapter绕过durable submit-intent，唯一public external-effect entrypoint是`ProductionStateCommitter.generate_voice_asset(request, provider, authorization)`。它在同一owned flow内执行preview/begin、R+2 submit-intent durability、permit mint、exact one provider call、materialize/probe/caption/candidate activation；所有lower-level lifecycle methods只用于same class/recovery/tests，不能直接触发transport。

`ProductionStateCommitter.record_voice_submit_intent()`在Manifest replace、directory fsync和reopen verification成功后才返回process-local、one-use `DurableVoiceSubmitPermit`。permit绑定attempt ID、Manifest revision/file hash、request fingerprint、destination和budget/egress authorization IDs；它没有public constructor/serializer，不能从durable JSON反序列化或由caller自填。`VoiceAssetProvider.generate()`只验证并把permit原样转交；唯一atomic consume owner是`ElevenLabsTransport`即将发出request的boundary，consume失败时zero network calls。`ai_video.production.__init__`只暴露provider-neutral protocol/request/result和safe `ProductionStateCommitter.generate_voice_asset()` path，不导出concrete `ElevenLabsVoiceProvider`、raw transport或可绕过permit的submit helper。restart后R+2没有permit，必须进入unknown-outcome/reconciliation contract，不得重新mint permit或blind retry。

P4 orchestration顺序固定为：

1. 构造 immutable request并验证 script hash。
2. `preview()`；unknown pricing、超预算、未授权 destination、unsupported output/timing能力均 fail closed。
3. P2A committer持久化 request/preview/budget/egress authorization。
4. P2A committer持久化 submit intent。
5. 仅由`ProductionStateCommitter.generate_voice_asset()`用one-use permit调用 provider一次。
6. 将 response materialize 到 attempt-owned staging，held-FD probe/hash，构造 alignment/caption/cost/provenance receipts。
7. P2A committer准备 candidate artifacts和candidate registry。
8. P2A committer原子选择新 registry并 coarse-clear active render state。

### Materialize, Probe, Hash, Register

`audio.py` 提供：

- `materialize_audio_candidate()`：只写由 `ProductionStateCommitter.voice_attempt_paths()` 返回的 contained attempt staging path；使用 no-follow/exclusive/atomic helpers，不接受 arbitrary caller path。
- `probe_audio_candidate()`：从一个 held no-follow FD取得 hash、size、decoded format/sample count/sample rate/channels/codec/loudness evidence；外部 tool若需要 path，只能使用 `/proc/self/fd/<fd>`，并将结果与同一 FD snapshot绑定。
- `audio_content_fingerprint()`：至少覆盖 file SHA-256、decoded PCM fingerprint、sample count/rate/channels、codec与loudness receipt identity。
- `build_audio_asset_record()`：纯函数，只有 probe/result/request/receipts complete时构造 registry record；不写 registry。

Provider claims只进入 provenance receipt，不可覆盖 measured truth。source bytes、normalized alignment、CaptionTrack、request/preview/outcome/cost/provenance receipt都必须是 immutable canonical artifacts，并由 candidate artifact hash exact-set覆盖。

### Local Import and Registry Activation

`ambience`、`sfx`、`bgm`以及user-supplied local `dialogue/narration`不经过voice provider或R+2 remote submit lifecycle，但仍不得绕过P2A：

1. `audio.py::AudioImportRequest`从caller提供的held source FD执行pure probe/hash并构造typed metadata；`captions.py::CaptionImportRequest`封住CaptionTrack/style identity；两者都不写active state。
2. `state_commit.py::prepare_audio_registry_commit()`使用existing `ProductionStateCommitter.prepare_artifact()`/`PreparedArtifact` primitives把audio imports、caption imports、style/receipt artifacts和完整candidate registry封成一个`StateCommitRequest(operation="audio_import")`。
3. `ProductionStateCommitter.commit()`执行existing generic candidate durability/Manifest replace/active registry selection，并在pair改变时coarse-clear `active_render_state`；P4 extension同时把Manifest升级到2.2、registry升级到2.1。
4. exact replay比较source hash、probe metadata、candidate registry和artifact set；local import没有paid/unknown provider outcome，但仍覆盖partial write、candidate orphan、final replace/reopen crash windows。

`prepare_audio_registry_commit()`只是existing committer module中的pure request builder，不是第二writer；`audio.py`、`registry.py`和provider adapter不得直接调用atomic replace。CaptionTrack-only import使用同一个builder/commit path。

### Cost and Provenance Receipts

新增 typed `VoiceCostReceipt` 与 `VoiceProvenanceReceipt`：

- cost receipt保存 currency、pricing unit、measured billable units、estimated upper bound、provider-reported cost或`None`、pricing snapshot ID、request/response IDs；不得把动态网页价格硬编码为永不变化的常量。
- provenance receipt保存 provider/model/voice/language/request fingerprint、script hash、output settings、alignment mode、tool/adapter version、egress authorization ID、license policy decision和sanitized provider IDs。
- raw API key、`xi-api-key` header、Authorization header、full raw response headers、user secret、dashboard URL和unredacted error body不得持久化或出现在CLI/test output。

class CaptionSegment(StrictModel):

class CaptionSegmentationPolicy(StrictModel):

Contract：

- script identity与transcript identity分开保存；normalized transcript改变必须产生新`transcript_hash`。
- segments必须按 source-relative integer samples严格单调、half-open `[start_sample, end_sample)`、非负、不可超出measured audio duration。
- words可选；存在时必须完整落在parent segment内并保持单调。provider不提供word timing时不得伪造。
- speaker使用stable project speaker ID；unknown speaker为`None`。P4不实现diarization推断。
- confidence是optional fixed-point 0..1000；provider未提供可比较confidence时为`None`。ElevenLabs forced-alignment `loss`不得通过随意取反伪装成confidence；原始loss保存于alignment receipt。
- segmentation policy/version进入 timing fingerprint；style reference不进入 transcript/alignment identity，但进入 caption style fingerprint与composition/render fingerprint。
- empty caption track允许仅在 explicit `captions_disabled` policy下不绑定；一旦绑定到composition，空segments、missing style ref、unknown source audio或hash mismatch均fail closed。

### Alignment Normalization

`captions.py` 提供：

- `normalize_character_alignment()`：解析 TTS with timestamps的character arrays/start/end seconds。
- `normalize_word_alignment()`：解析forced alignment返回的word bounds；不承担diarization。
- `seconds_to_source_sample()`：只用`Decimal(str(value))`和明确rounding policy转为source sample；禁止binary float累计。
- `segment_caption_track()`：只执行versioned deterministic policy。

- `caption_style_fingerprint()`：覆盖style reference artifact ID/hash及renderer-consumed style schema。

Provider timing先在source audio sample rate下canonicalize；只有`composition.py`把它映射到composition sample rate、absolute samples和frames。`captions.py`不得知道shot order或global start。

### Timing Rules

- `resolve_composition()`一次性解析shot order、visual frame spans、audio absolute sample spans、caption absolute sample bounds与caption frame intervals。
- `_sample_at_frame()`（或同一module中的单一replacement）继续是frame/sample rounding owner。character/word seconds只在`captions.py`转换一次为source samples；P4要求source/composition sample rate一致，absolute placement和sample/frame mapping再使用integer rational arithmetic及明确floor/ceil policy，禁止每个adapter自行换算或隐式resample。
- caption cue的sample timing是canonical；frame interval用于renderer display，必须由timeline owner生成。renderer不能用CSS/JS浮点秒重新决定cue boundary。
- `start_frame=floor(start_sample * fps / sample_rate)`；`end_frame_exclusive=ceil(end_sample * fps / sample_rate)`，并验证非空、contained、deterministic。若实现选择不同rounding，必须先把exact公式与RED fixture写进tests，再修改代码；不得保留两套算法。
- `total_samples`由final visual frame boundary与sample rate唯一计算。fixed composition不因尾部audio自动增长；voice-driven duration在shot resolution阶段先确定frame count，再重新得到canonical total samples。
- old silent timeline `2.0`加载后等价于`audio_spans=()`/`caption_cues=()`；其existing content hash/fingerprint验证不能因default serialization被悄然改写。
- `timeline_fingerprint()`继续是唯一composition fingerprint owner，并覆盖新增audio/caption resolved fields。不要新增`audio_timeline_fingerprint`与之竞争；下游细粒度fingerprint仅作为输入证据。

## Crash, Replay, Unknown Outcome, and Rollback

### Durable Revisions

以base revision `R`为例：

| Revision / Window | Durable State | Allowed Next Action |
| --- | --- | --- |
| before `R+1` | no request/preview/authorization | 禁止submit；安全重建pure request/preview |
| `R+1` | running voice attempt，exact request、preview、budget reservation、egress authorization durable | exact replay可进入submit-intent；mismatch拒绝 |
| `R+2` | `submit_intent` durable，明确即将对exact provider/destination发送exact request | 只允许单次provider call；crash/timeout/连接断开后不得blind resubmit |
| provider known rejection | terminal failed receipt durable | exact replay返回same failure，不重发 |
| response returned but outcome bytes/receipt not durable | active registry仍old；真实provider outcome可能已计费 | 标记`OUTCOME_UNKNOWN`；只有provider官方reconciliation能力与新显式授权才能继续 |
| `R+3` | audio/caption/receipts/candidate registry exact artifact bundle durable并由attempt pointer引用；active registry仍old | explicit recovery只reverify/preserve并标记interrupted；caller随后exact replay `activate_voice_assets()`完成R+4，不再调用provider |
| `R+4` | one Manifest replace选择candidate registry，blanket-clear `active_render_state`，attempt succeeded | replay返回same active identity |
| final replace后reopen/fsync result不明确 | disk state可能R+3或R+4 | 返回typed outcome unknown；reopen exact manifest判定，不猜测、不重复provider call |

### Idempotent Replay Identity

exact replay必须比较：

- attempt ID、operation、base project/registry/render pointers；
- immutable request hash、script hash、provider/model/voice/settings/output format；
- pricing snapshot、budget reservation、egress destination/authorization；
- candidate artifact exact-set hash；
- provider request/idempotency/request ID（若official API实际提供且已持久化）。

任一差异都返回typed conflict，不复用attempt。不能因为script text相同就忽略voice/settings/pricing/authorization差异。

截至本plan核对的official TTS contract没有足够证据承诺client-supplied idempotency key或通用request-status retrieval。因此默认live adapter必须按“no safe retry after submit intent”设计。若implementation day official API增加可验证idempotency/reconciliation，先新增compatibility test与plan amendment；不得凭SDK内部行为推断。

### Explicit Recovery

`ProductionStateCommitter._recover_attempts()`必须新增voice operation分支：

- R+1且未submit：记录interrupted，保留request/preview artifacts；不自动submit。
- R+2：记录`OUTCOME_UNKNOWN`；不自动retry。
- provider ordinary known failure：保持terminal failed。
- candidate不完整：删除仅attempt-owned incomplete temp；完整orphan preserve/report；不切active registry。
- R+3 candidate complete：explicit recovery只reverifyhash/path/base identity、preserve referenced candidate并标记interrupted；不得因recovery本身选择new registry。随后由caller显式exact replay `activate_voice_assets()`完成R+4且不调用provider。
- R+4 already active：收敛为succeeded exact replay。
- unknown artifact、symlink escape、hash mismatch、base pair drift：fail closed并保留证据。

任何reader、CLI startup、provider adapter构造或render call都不得隐式调用recovery。

### Rollback

P4 runtime rollback步骤必须是：

1. 禁用/移除P4 public construction/entrypoint；不删除state。
2. 保留Manifest 2.2、registry 2.1、Composition/Timeline 2.1 reader与explicit recovery。
3. 保留already active audio/caption assets与receipts；不得downgrade或把它们重写成generic 2.0 records。
4. old P3 silent compositions继续load/render；new P4 compositions可read/audit，但在disabled adapter下typed-fail执行。
5. 不删除unknown-outcome attempts、orphans、cost/egress/provenance evidence。
