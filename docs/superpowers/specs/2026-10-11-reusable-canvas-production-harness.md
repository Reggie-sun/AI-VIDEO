# Reusable Canvas Production Harness

Date: 2026-10-11
Status: Proposed — spec-only；尚未实施，未授权媒体调用。

## Goal

从多种现有画布中提取可重复的制作方法，接入现有 AI-VIDEO，使不同故事能够通过同一流程完成
素材组织、镜头创作、连续生成、声音编排及整片交付。更换故事、角色、场景和镜头内容主要修改项目数据，
不需要故事专属代码、临时上传脚本或每次重新搭建执行链。
“多画布”首先指不同作品复用同一套流程，不要求把多个画布自动合并为一部作品或建立跨画布调度系统。

这里的“通用”指在声明支持的制作类型与 Provider 能力范围内复用，不承诺支持任意平台节点、任意模型、
任意剪辑效果或逐像素复刻。复用原画布的创作内容、参考职责和依赖结构，不保证随机生成结果与原片完全一致。
本 spec 定义目标与验收；本轮不写 implementation plan、不改代码、不抓取新画布、不生成或修改媒体、不训练模型。

## Current Baseline And Scope Correction

当前可复用入口已经存在：

- `scripts/canvas_reference_packet.py` 保存生成节点的 prompt、引用和来源信息。
- `scripts/canvas_sequence_packet.py` 保存选定故事顺序、重复 occurrence、原始参数与参考绑定，
  校验显式边界；缺失 authoring、冲突或缺证均不能伪装为可执行。
- `scripts/canvas_sequence_handoff.py::build_canvas_sequence_planning_request` 核对 occurrence 与已存在、
  已批准 Shot 的身份和顺序，调用 `planning/sequence_continuity.py::build_sequence_video_planning_request`。
  它要求调用方提供真实执行证据，不自动完成项目创作、整链执行或声画交付。

已有工程测试不能证明多故事通用生产已经完成。新目标补齐用户可操作的整链衔接，优先复用这些能力；
不把新增一个导出包、一个校验器或一份使用说明当作完成。

[上一份 preparation spec](2026-10-10-canvas-sequence-preparation.md) 继续描述其已实现的有限范围，
但不再代表本目标的完整验收范围。《反向之地》《白带子》的原素材、偏差及历史采用结论保持。
长杆→空手、某个转场不成立等只属于相应项目的数据问题，可用于验证检测与停点，
不要求先修好这两部作品才能完成通用 Harness；也不能为了通过工程验收把这些问题判为通过。

## Corpus And Holdout

起步使用 5 个提取样本（已有 2 个加新增 3 个）及 2 个独立保留样本；这是可调整的取证规模，
不是代码里的最低画布数，更不是统计泛化保证。先只读登记候选的制作特征、完整性和用户评价，再选样本。
不能仅凭画布名称、缩略图或数量判断代表性。

样本集合应覆盖以下差异，允许一个画布覆盖多项：

| Coverage | 要观察的制作关系 |
| --- | --- |
| Dialogue and performance | 说话、听回应、注意与情绪变化、动作过渡和落定 |
| Action and state | 位置、持物、动作阶段与可见结果的跨镜承接 |
| Scene transition | 切镜、时空变化、遮挡等有意改变；明确哪些状态不必继承 |
| Output dependency | 后镜实际消费前镜视频、尾帧或其他输出，而非只共用参考图 |
| Audio causality | 声音触发人物反应、跨镜声音连续，以及最终混音 |
| Revision evidence | 失败版与采用版及选择理由；保留不符合共性假设的反例 |

同一作品的多个版本不自动算独立样本。保留集在规则与接口冻结前不进入细节提取；记录样本分配及版本。
若为保留集修改了共享语义或代码，该集转为开发样本，修订版需另选未参与设计的样本验证；
不能持续换样本直到得到通过，也不预读全部画布再声称盲测。
覆盖已足够且新样本只增加创作内容时停止扩样；只有明确能力缺口才增加对应类型。

## Input And Preservation Contract

原始画布快照与可用素材是取证来源；Markdown/HTML 是供人核对的投影，不是另一个 Production 状态源。
HTML 保存成功不证明媒体、连线或历史版本已经保存。只有 MD/HTML 的输入可登记为资料，
必须列出缺项并补证后才具备执行资格，不根据页面排版补造依赖。

每个来源至少保留：

- 来源标识、捕获版本、快照完整性及内容 hash；可访问指针与实际获取到的素材 bytes/hash 分开。
- 节点身份/类型、原始 prompt 与结构化引用 slot、原始生成参数、参考素材及各自职责。
- 引用关系、生成依赖、显式故事顺序和时间线 occurrence；同节点重复出现不去重，候选版本不自动拼入成片。
- 输出版本及用户选用信息；“节点当前 resourceId”不能代替具体采用的输出 bytes。
- 原时间线的 trim、speed、audio 设置及未支持字段；源顺序不直接成为第二条生产 timeline。
- 用户评价、已知偏差及证据范围；没有听过、看过或找不到原素材的内容标为未评估/缺失。

原文与适配后的内容分别保存，并能展示差异和原因。默认新生成 480p，原画布的分辨率保留在观察值中；
用户明确要求才覆盖默认。Provider 不支持所需规格时显示能力缺口，不静默升档、换模型或改创作目标。
模型标识、版本和实际能力留在项目/执行绑定中，不把 Seedance 或 H3 的特定参数变成通用制作规则。

## Reusable Authoring Contract

通用部分组织创作问题与证据，不硬编码某条 prompt 或某个故事。每段按实际需要表达：

1. 剧情目的、观众必须看见/听见的事件，以及开场状态、触发、行动/反应、结果。
2. 角色/场景身份、每份参考负责的方面；图片区分开场、经过状态、结尾和一般参考。
3. 表演的注意对象、变化动因、动作过渡和落点；不以动作数量或“自然”形容词代替表演设计。
4. 摄影和空间约束、剪接意图、声音/对白原文、说话者、声源及其与动作的先后关系。
5. 相邻段保持、显式改变或允许释放的状态，边界类型，以及所需前段结果的具体引用。

这些是语义要求，优先映射既有 Story、Character、Scene、Storyboard、Shot 和连续性类型，
不预设新建平行的通用 schema。无对白、无人物或有意跳切的作品不用填伪造的对白/角色/连续动作。
画布坐标、相邻编号、共用图片或引用边均不足以自动推断剧情顺序和连续义务。
文本分析可以提出草案；涉及含糊的剧情、身份和允许变化时由导演/用户作决定，不由 parser 猜测后封成事实。

## End-to-End Workflow Contract

未来实现应提供同一受支持入口贯穿以下步骤，允许按真实人工决策点暂停和恢复；
不要求无人值守，也不能要求用户或 Agent 每次手工补造内部 identity/hash/receipt 或重写脚本。

| Stage | Required behavior and boundary |
| --- | --- |
| Inspect | 读取显式来源和选定链，展示缺项、候选版本与未支持能力；离线检查无提交副作用 |
| Author | 形成可审查的既有创作 artifacts，绑定参考职责、声音目标和前后状态；保留原文与适配差异 |
| Prepare | 通过现有 Project/Registry/Planner/Router 解析身份、能力和执行输入；输出实际请求预览及有限调用上限 |
| Execute | 按用户已授权范围通过既有 adapter、budget、permit 和 committer 执行；unknown 停止，不盲目重试 |
| Handoff | 前镜实际 MP4 及逐镜 Gate 合格后，消费真实 accepted source/末态证据准备后镜；不消费 prompt 中想象的末态 |
| Compose | 沿已有 composition/audio/render owners 组装；核对采用素材、trim、速度、完整声音及最终顺序 |
| Deliver | 展示 exact 成片供完整听看，记录采用版本与已知偏差；技术成功不代签作品质量 |

源导入、创作批准、Generation、验收与采用是不同事实；中断恢复须从既有持久状态重开，
不得依赖聊天记忆完成状态转换。已有成功副作用不得因重启或重复命令而再次提交。
有意场景重置不能强制继承所有前态；需要直接连续的后镜则不能偷偷降为独立镜头。
参考策略按镜头需要选择，不要求每镜都用上一尾帧，也不把增加参考数量当作通用修复。

## Ownership And Change Boundaries

| Responsibility | Existing owner to reuse |
| --- | --- |
| 创作实体及修订 | ProductionProject 与现有创作 contracts |
| 素材身份、来源和 bytes | Registry |
| 可变状态、写入、采用与恢复 | Manifest / ProductionStateCommitter |
| 连续性规划及真实前序证据 | planning/sequence_continuity.py 与 production/_sequence_source.py |
| 依赖变化与重建范围 | 既有 Dependency Graph / resolver |
| 帧、采样、顺序和 trim | ResolvedTimeline |
| 最终渲染及音轨编排 | HyperFrames 与现有 composition/audio path |
| 验证证据 | 现有 QA/媒体 Gate、用户完整听看反馈；开发 Harness 不代签 |

来源格式适配与故事数据分离。不同输入格式可以有解析适配器；相同格式下新增故事不能要求一个新的故事适配器。
开发脚本不成为 Product Runtime 的反向依赖。只有查明既有 owner 缺少必要能力时才在其边界内补齐，
不新增第二条 timeline、状态库、通用插件系统或规则引擎。

修改角色/参考/前镜输出时，依赖重验与 rebuild frontier 由既有 owner 推导；
同时考虑参考、声音与其他非相邻依赖，不只检查前后一镜。重验不等于自动重新生成，
旧版本、历史消费及接受结论保留；新的提交仍需满足当前授权与预算。

## Automation And Human Decisions

适合自动化：结构解析、身份/bytes/引用完整性核对、合法组合校验、请求预览、依赖失效计算、
授权内执行与恢复、原素材和输出版本归档、技术媒体检查及证据汇总。

需要人参与：创作目标与实质改写、重要歧义/版本选用、表演自然度、对白听感及最终完整声画采用。
不新增每镜机械确认；沿用已有明确授权和验收 gates，在真实创作分歧处停下。
ASR、抽帧、播放成功、音轨存在只能证明各自检查项；无法实际听辨时明确交用户确认。
用户接受一个带偏差的版本，不改写为所有原要求 PASS，也不自动豁免后镜 gate。

## Acceptance Criteria

以下是未来实现验收，不是本 spec 已通过的测试：

| ID | Criterion | Required evidence |
| --- | --- | --- |
| AC-1 | 来源忠实且可追溯 | 对选定开发画布逐项对照 prompt/slot/参数/关系/occurrence/输出版本；遗漏与未支持项显式报告 |
| AC-2 | 不按故事写代码 | 提取完成后冻结共享实现与规则；至少 2 个保留画布仅填项目数据、选素材、作正常导演决定即可使用同一入口，无故事专属分支或脚本 |
| AC-3 | 支持完整连续链 | 至少覆盖直接承接和有意换场两类；通过 canonical reader/committer 的集成验证到真实 accepted-source seam；拒绝错序、陈旧输出、缺证与非法状态释放 |
| AC-4 | 不只是导出工具 | 同一流程完成从来源/创作到已有执行、交接、composition、交付的衔接；离线 scripted Provider 可验证控制流，但明确不算实拍证明 |
| AC-5 | 可恢复且变更局部化 | 重启不重复已完成提交；unknown 不自动重试；更换一个输入由 canonical graph 标明受影响项，未相关项目与历史 bytes 不变 |
| AC-6 | 能发现问题而不修辞抹平 | 缺素材、错误选用、来源冲突和原对白变化均有定位；案例失败只阻断相应单元，不成为全局禁止条件 |
| AC-7 | 真正的声画交付 | 后续明确授权后，至少 1 个保留画布的完整短剧情单元走现有流程形成 exact 成片，由用户完整听看认可；默认 480p，已知偏差单列 |

离线 AC 与真实制作 AC 分开报告；AC-7 未执行时只能说“工程流程已验证，制作效果未验证”。
真实批量制作前遵守现有代表性 Pilot 要求；具体单元、Provider、时长、调用上限在执行前封存，
本 spec 不自行授予这些调用。原画布成片好看不能代替本 Harness 的实际交付证据。
保留集失败时区分导入错误、流程缺口、能力不支持与媒体质量问题，不用一类证据替另一类开脱。

## Cost And Stop Conditions

先看少量差异明显的画布，不要求全量抓取/全文反复传给模型。缓存内容身份稳定的提取结果，
只重读确实变化及依赖受影响的内容。后续实测记录解析/人工整理成本、实际模型输入与输出 usage（若可得）、
视频物理提交数、重试原因、时长与规格；未知费用不估成账单，不把工程 Agent tokens 与视频计费混为一谈。

- 反复出现同格式新故事就要改代码：暂停扩量，修正抽象边界，不不断堆案例分支。
- 关键来源无法保存：保留资料与缺口，不声称可忠实重建，不据此付费试错。
- 流程可走通但表演或声画未达标：单独评价当前制作路线，不追加工程层来替代制作判断。
- 达到已授权调用上限或结果 unknown：停止该执行单元，保留真实历史，不用换名重置。
- 没有具体且实质不同的改法：不建议同配置重复抽样。

## Non-Goals

本 scope 不训练/微调视频模型，不构建即梦 UI 克隆，不新增 Provider、安装 Skill 或迁移开源生成栈，
不追求一次实现所有画布节点，不修复旧反击或两部样本的所有素材，不自动改变对白、角色或艺术要求。
跨案例做方法提取不是模型训练；是否训练只有在未来有独立证据和明确授权时另行决策。

## Self-Review And Open Evidence

Parent self-review：目标是可重复的多故事生产，不是两个案例专用工具；连续性与完整声画交付都进入验收。
采用现有 owner，未设第二状态/时间线或新自动验收权；保留集防止在旧样本上自证。
本文件是 proposed spec，不能作为已实施 baseline、模型定律或付费执行许可。

仍需后续取证：新增画布链接和完整数据、代表性/采用评价、可独立保留的样本、各原始输出版本对应关系。
来源格式与实际能力缺口可能影响实现范围；应先按本 spec 的少量样本调查再写实现计划，
不因截图显示画布很多就提前承诺全部支持。
