## 2. 不满意的根因（对照作者原始记录）

| 使用者的感觉 | 实测或对照 | 作者怎么做 |
|---|---|---|
| AI 味重 | 底片全用 Codex `image_gen`，光滑、干净、CG 海报感 | Midjourney v8.2 `--raw --hd` 加导演个人 profile；每条 prompt 以同一组风格词收尾：“fine silver grain”“cinematic 35mm film still”。导演否过“way too.. gray … loses the Midjourney magic” |
| 场景单调 | 84 镜几乎都在同一个蓝色机房 | 每个 Look 是一个硅谷梗，各有真实地点：车里、高速、广告牌、工地、街头、白天的雾 |
| 人物只会摆姿势瞪眼 | 数字人镜头全是正面压下巴瞪镜头 | 她一直在做事：走秀、摔、吐舌、调帽子；每镜是一个有互动的事件 |
| 概念太空太套路 | 一则新闻撑整部片，靠克隆人、门缝这类抽象寓言 | 研究代理收集当季的真实梗与事件，并逐条核实；三个导演代理（时尚片、梗密度、叙事）各出一版分镜，再评分、合并 |
| 歌词太少 | 我们 184 词／4:22，每分钟 42 词；人声空档长，副歌反复同两句 | EV 447 词／5:06，每分钟 88 词；主歌是一句一梗的冷面念白，四个写手（密度、张力、钩子、时尚）各写一版，再评分、合并、批评，最后做音节检查 |

结论：问题出在上游的概念、歌词和美术工具，不在剪辑。所以要从作者的第 1 个检查点（概念）重新开始，并且照作者的话：“新歌就是新片”。

## 3. 照作者的顺序做（`wiki/start` 的 13 步、6 个检查点）

| # | 阶段 | 产出 | 检查点 |
|---|---|---|---|
| 1 | Brief | 使用者原话、禁区、密度目标（主歌每分钟 ≥80 词） | |
| 2 | 研究 | 当季 AI 梗与事件库，每条由独立核实代理查证 | |
| 2b | 概念 | 三个提案，每个 ≤120 字：前提、贯穿装置、主角、弧线、一个风险 | **1 · 选概念** |
| 3 | 歌词 | 四个写手（密度、张力、钩子、叙事）→ 评分 → 合并 → 批评 → 音节检查 | |
| 4 | 歌 | Suno 逐轮出 take，使用者凭耳朵挑 | **2 · 选歌** |
| 5 | 听 | 分轨、节拍、逐字时间（先人工听查）、重音 | |
| 6 | 她 | canon 文字＋四张测试底片（用新的底片工具） | **3 · 认脸** |
| 7 | 分镜 | 三个导演代理（时尚片、梗密度、叙事）→ 评分 → 合并；每镜写明歌词、字体模式、底片 prompt、机位、图形要解释什么 | **4 · 审分镜** |
| 8 | 底片 | 批量出图，编号联系图，每镜一张 | |
| 9 | 片段 prompt | prompt 本与费用，花钱前先读 | **5 · 花钱前** |
| 10–11 | 片段、剪辑、动效 | 先给 20–40 秒样片，再出全片 | |
| 12 | 检查与渲染 | 歌词 N/N、闪烁、单帧突跳 | **6 · v1** |

**沿用的东西**

- 工具与管线：motion-kit 引擎、HyperFrames、节拍图、CTC 逐字对齐、Suno 网页自动化、数字人和 Seedance 车道（`ep01/v3/gen/`）。
- 规则：事实核查（`ep01/fact-check.md`）、门缝信号红的世界规则。
- 角色 IRIS 的身份：银白短发、耳挂红灯、立领红线。这些在新底片工具下要重新过“认脸”检查点。

**不再用的东西**

- 分镜 v2、a1/a2 与 T4 这首歌。

**作者的额外教训，照做**

- 先在一个镜头上找到方法，再铺到整部片。
- 尽早给 30 秒样片，不要等全片做完。
- 观感只由使用者判断，Agent 的 PASS 不代替。

## 4. 等使用者决定的事

1. **底片工具。** AI 味的主要来源是底片工具。作者用 Midjourney 网页版加自己的 profile，Midjourney 没有官方 API。
   - 使用者有账号：我们写 prompt，在使用者的浏览器里出图。
   - 没有账号：改用即梦图片生成并加作者那组胶片风格词，先做对比试验。
2. **研究范围。** 作者的密度来自当季的一整库梗。可选：
   - 保留 DNS 事件做核心，周围加当季 AI 梗；
   - 扩大到当季 AI 新闻与梗；
   - 只讲这一件事。
