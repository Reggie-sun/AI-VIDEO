## Purpose

本 roadmap 只定义 phase dependency、gate、parallel boundary 和 slice output。每个 runtime phase 仍需单独的 implementation plan、明确授权、tests、rollback 和 acceptance。不得把本文件当作一次性执行计划。

Documentation Contract Gate只在Development Governance中验证本roadmap/spec metadata的owner路径与
static repository anchors；它不把roadmap升级为runtime truth，也不能判断任意叙述段落或architecture
论证是否仍正确。动态implementation/evidence状态继续由`docs/v0.2-runtime-baseline.md`拥有。

## Parallel Work Rules

以下 work 可在 contract 稳定后并行规划，但 concurrent writers 必须使用独立 branch/worktree：

- P3、P4 和 P7 都依赖 accepted P2 + P2A。P3-P7 与 Base AI Comic E2E 已在 local `main`；P7 不是P5前置。
- P3 负责 resolved visual/composition timebase 和 renderer boundary；accepted P4 只扩展 audio/caption data，generated-MP4 compatibility只扩展visual media kind与source trim，仍由同一个 `ResolvedTimeline` 独占 order/frame/sample/timing，不得另造 timeline owner。
- P7 只负责 image asset production/provenance；它已复用未修改的 P5 resolver，不拥有 renderer、video generation 或 automatic upstream-reference regeneration。
- P8 provider lifecycle与generated-MP4 composition compatibility是两个独立slice。后者只消费已注册/本地验证并满足exact metadata的H.264 MP4，已完成frame-accurate P3/P4 integration；它不使fetched candidate自动成为active Registry/Project/Graph asset，也不授权任何future cloud submit。Paid Provider Gate、Budget、Egress、secret redaction和crash-safe job persistence仍分别适用。

以下 work 不得并行落地：

- 两个 writer 同时修改 ProductionProject/Asset Registry schema owner。
- HyperFrames 和 Remotion 同时争夺 canonical renderer/default path。
- P5 invalidation resolver 与另一个 ad-hoc stale implementation 并存。
- P6 strategy-aware QA 与 current heuristic auto-edit 形成两条 production control path。

## Mandatory Gates

### Integration Base Gate

开始 P2A 时已执行并记录；任何后续 runtime slice 仍必须执行并记录：

```bash
git status --short --branch
git log --oneline --decorate -10
git rev-list --left-right --count origin/main...main
```

选择包含 accepted P1-P8 与 Base E2E 的 local `main` 作为后续slice base。不得从 `origin/main` 开始后无意遗漏 local-only commits，也不得把 local ahead state 当作 GitHub runtime truth。

### Renderer Gate

P3 Renderer Gate 已完成：project-local pin 为 `hyperframes@0.7.103`，验证浏览器为 Chrome Headless Shell `152.0.7928.2`；compatibility 与 committed-fixture proof 均在 fresh user/network/PID namespace、controlled env 和 full process/network trace 下通过。P3 未实现 Remotion adapter，也没有 alternate renderer fallback。

### V2 State Commit Gate

P2 只读取并验证已存在的 project、creative artifact、registry snapshot 和
Manifest pointer。P2A implements the accepted write/activation boundary and is present in `origin/main` via P5 ancestry. The implementation provides:

- temporary snapshot write + file fsync + promote-without-overwrite + parent-directory fsync + reopen verification；
- durable attempt lifecycle writes may record running/failed state; after snapshot verification, only the final active-pointer Manifest replace is the logical commit point；
- explicit recovery with crash-injection coverage for partial temporary files, complete orphan snapshots and pointer switch；
- no change to Legacy Manifest v1 owner。

## Slice Planning Rules

1. 只覆盖一个可独立验收的 slice。

4. 使用 fake/no-network tests 作为默认 CI。
5. 对 external tool version、license、API 和 pricing 在 plan 当天重新核对。
6. 不把 planned next phase identifier 引入 current runtime。
7. 完成后更新 baseline、README 和 contract matrix，但只写已验证 behavior。
