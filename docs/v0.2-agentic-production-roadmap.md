## Parallel Work Rules

以下 work 可在 contract 稳定后并行规划，但 concurrent writers 必须使用独立 branch/worktree：

- P3、P4 和 P7 都依赖 P2，可以由 non-overlapping teams 并行。
- P3 负责 resolved visual/composition timebase 和 renderer boundary；P4 负责 audio/caption data，不得另造 timeline owner。
- P7 只负责 image asset production/provenance，不得修改 renderer 或 dependency resolver。
- P8 的 read-only design exploration 或 plan drafting 可以在 P2/P5 contracts 稳定后开始，但任何 P8 runtime implementation 必须等待 Base AI Comic E2E acceptance；任何 cloud submit 还需 Budget、Egress 和 crash-safe job persistence gates。

以下 work 不得并行落地：

- 两个 writer 同时修改 ProductionProject/Asset Registry schema owner。
- HyperFrames 和 Remotion 同时争夺 canonical renderer/default path。
- P5 invalidation resolver 与另一个 ad-hoc stale implementation 并存。
- P6 strategy-aware QA 与 current heuristic auto-edit 形成两条 production control path。

## Mandatory Gates

### Integration Base Gate

开始 P2 前必须执行并记录：

```bash
git status --short --branch
git log --oneline --decorate -10
git rev-list --left-right --count origin/main...main
```

选择 local P1 base、先 push/merge P1，或从 origin branch 并显式 cherry-pick P1。不得把 local ahead state 当作 GitHub runtime truth。

### Renderer Gate

P3 必须先验证 HyperFrames 的当前 plugin/CLI/version/license/runtime requirements，再决定 installation mode。该 gate 需要单独授权安装 Node dependency/tool。P3 不得顺带实现 Remotion adapter。

### Paid Provider Gate

P4 的 ElevenLabs real call 或 P8 的 cloud video real call 前，必须已有：

- explicit opt-in；
- budget upper bound and reservation；
- egress preview；
- secret redaction；
- crash-safe request/job receipt；
- fake transport tests；
- explicit live-test authorization。

### Base AI Comic Gate

P8 之前必须证明：

```text
Story -> reusable Character/Scene state -> image assets
-> voice -> CaptionTrack -> ResolvedTimeline
-> deterministic render -> strategy-aware QA
-> selective repair -> final.mp4
```

这个 proof 不得配置 Video Provider。

## Slice Planning Rules

每个 phase implementation plan 必须：

1. 只覆盖一个可独立验收的 slice。
2. 指定 exact owner、old path to retire、unchanged contract 和 focused verification command。
3. 列出 schema migration 和 rollback；没有 migration 也要明确写 `none`。
4. 使用 fake/no-network tests 作为默认 CI。
5. 对 external tool version、license、API 和 pricing 在 plan 当天重新核对。
6. 不把 planned next phase identifier 引入 current runtime。
7. 完成后更新 baseline、README 和 contract matrix，但只写已验证 behavior。
